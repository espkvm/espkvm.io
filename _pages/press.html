What people use it for

The situations readers recognise, in the order they come up. There is a longer version of each in When remote desktop cannot help, with a drawing for every one - those drawings are mine and free to reprint.

  • A parent's computer in another city. The fix is usually small - press a key, choose a different boot entry, undo an update - and over the phone it takes an hour. Through a browser it takes two minutes, and they do not have to touch anything.
  • A home server nobody sits at. A machine in a cupboard with no screen and no keyboard, which works for months and then one day does not answer. Without a screen there is no way to see why.
  • A house that runs on one small computer. When the machine behind the lights, the heating and the front door stops, nothing is running on it for the usual remote tools to talk to.
  • Installing a system from far away. The device offers a disk image from its card as if someone had walked over and plugged in a USB stick, so a machine with an empty disk can be given a fresh system.
  • A machine that is switched off. Two wires to the power pins on the motherboard, and the button in the browser does what the button on the case does.
  • Anything expensive to reach. A workshop, a summer house, a rented server in another country, an old machine running one program that must not be touched. Getting to it costs more than fixing it.

What is unusual about it

Plenty of projects put a screen in a browser. These are the parts I would write about if I were you.

  • The screen can be read as text. When the machine is showing a BIOS, a boot menu or a console, you can select that text with the mouse and copy it. It is not OCR: a text screen is drawn from a fixed set of character shapes, so each cell is looked up in a table of those shapes, and is either certain or marked unreadable. There is no "recognised with errors" to mislead anyone later.
  • It can watch that screen while nobody is connected. Give it phrases - "no boot device", "kernel panic" - and it raises an alert when one appears, in its own log and in Home Assistant.
  • It boots the target from an image on its card, so a machine with an empty disk, in another building, can be given a fresh system without anyone going there.
  • Installing it is a web page. Plug the board into a laptop, open the flasher, click. No toolchain, no compiler, no command line.
  • Remote access is built in. WireGuard and Tailscale both run on the device, so reaching it from outside the house does not need a second box or a forwarded port.
  • The smallest build is the size of a matchbox and takes power and network from one PoE cable.

Everything it does

The whole list, for checking a sentence against. Everything here is in the released firmware today; the README keeps the same table with the fine print.

Screen and control

  • Video capture that follows the target's resolution changes
  • H.264 or MJPEG streaming
  • Keyboard, absolute and relative pointer, media keys
  • Pasting text — US English, Russian, Czech, Ukrainian, Lithuanian layouts
  • Key macros of your own
  • Use from a phone — touch trackpad and an on-screen keyboard
  • Several viewers at once, one in control, with takeover
  • Waking a sleeping machine from the keyboard

Beyond the screen

  • Virtual media — boot the target from an image on the card, or a small one in the device's own flash
  • Power and reset buttons through the motherboard header, and the power LED read back
  • Wake-on-LAN
  • Reading a text screen as text, and copying it
  • Noticing a screen that has gone one flat colour
  • Watching the screen for phrases while nobody is connected
  • Guessing the target's operating system from how it enumerates USB

Getting to it

  • Ethernet, or WiFi on boards with a co-processor — join a network or be one
  • A rescue hotspot with a captive portal
  • WireGuard or native Tailscale, built in — no port forward, no gateway
  • HTTPS with a certificate the device issues itself, or one you bring
  • A login, and a password reset with the board's button
  • A viewing token for dashboards — opens the picture and the figures, nothing that touches the target
  • IPv4 and IPv6, with nothing to fill in

Living with it

  • Firmware updates over the network, into a spare slot, with rollback
  • Settings to a file and back — no secrets in it
  • An optional status display — an I2C OLED or a round colour LCD
  • Home Assistant over MQTT — sensors, buttons, an update entity, a camera of the screen
  • Diagnostics, capability reporting and a device log
  • A crash dump kept in flash when the firmware panics
  • Thermal protection

What it is not

It is not a replacement for remote desktop. When a computer is healthy, remote desktop is faster and sharper and can move files; an IP-KVM is for the times when there is nothing running to connect to. 1080p arrives at about 22 to 24 frames per second on current silicon, which is right for fixing a machine and wrong for using one all day. And it is a device with complete control of a computer, so it belongs on a home network behind a VPN, not on the public internet - the documentation says so in the same words.

LicenceApache-2.0
Boards supportedEight, across fifteen published images (some silicon revisions need their own)
HardwareAn ESP32-P4 board and an HDMI capture board; optionally a status display, an optocoupler for the power button, and a microSD card
VideoH.264 encoded on the chip, or MJPEG; about 22-24 fps at 1080p on revision 3.x silicon
Written inC on ESP-IDF, about 30,000 lines; the console is Vue 3 and TypeScript, built into a single file and served from the device's own flash

Logo

The mark is the name: it spells ESP-KVM in two lines, so there is no separate wordmark to chase. It comes in enough colours to sit on whatever background your page has - a badge with its own square, or bare glyphs in one colour. Please do not restretch it, recolour it into something else, or set it on a busy photograph; it is a pixel grid and it stops reading immediately.

For one-colour printing there are pure versions with nothing behind them: black SVG or PNG, and white SVG or PNG. The two colours the mark normally uses are #0e1116 and #e6edf3.
